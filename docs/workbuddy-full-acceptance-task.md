## 3. 本轮优化的专项复核

- SQLite 保持连接：验证显式启用与退出释放、重复启用、数据目录切换、后台/前台并发、Windows 文件占用、备份与恢复、长期锁和 WAL 增长。不得牺牲事务和账号隔离换取耗时下降。
- 日期缓存：验证紧凑日期、秒/毫秒、北京时区、午夜和非法输入；对象/记录变化后不复用旧值；缓存大小有界，不跨账号留下内容。性能比较同时核对统计结果。
- 生命周期计数：区分累计注册次数和仍然存活的监听；跟踪目标是否仍被引用、销毁是否真实发生。只有测量计数增长不能直接认定内存泄漏，堆稳定也不代表所有资源释放。
- 若优化阶段用 preload shim 绕过运行环境的同步子进程故障，记录 shim 作用与测试条件；能在正常独立进程运行时优先验证原生测试入口。shim 条件下通过与原生通过分别报告，环境问题和项目失败分开。
- 检查新增基准和诊断文件是否真有维护价值；保留证据，避免混入生产入口。无收益、回归或不可解释噪声的优化撤回相应局部补丁，而非重置整个工作区。

## 4. 问题处理闭环

每项记录严重度 P0–P3、触发操作、影响、代码位置、复现证据、原因、最小修复、测试及状态。先处理数据损坏/泄露、崩溃、账号串用，再处理功能错误、性能与可维护性。

局部问题按“复现 → 最小补丁 → 定向复验 → 相关完整回归”逐项推进。一般控制在一个行为路径和 1–2 个生产文件；需要更大改动时拆分并说明，涉及架构/持久格式/重大外部行为时独立提案。

修复引入回归立即收窄或仅撤回该补丁；同一问题连续 2 次修复仍恶化，记录根因与后续提案，保留用户修改。禁止改断言、隐藏异常、跳过失败或虚构通过来让验收变绿。
