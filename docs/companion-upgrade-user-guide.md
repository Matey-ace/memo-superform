# 陪伴模式使用说明（首版）

本版本给 MeMo 的陪伴角色加了长期记忆、多角色批量安装，以及**真实的**词汇学习进度与
结算奖励。这份说明讲清楚它怎样工作、你会在哪里看到变化、以及哪些情况下它**故意不**给奖励。

---

## 一、长期记忆

### 它记什么

分三类，用途不同：

| 类型 | 来源 | 例子 |
| --- | --- | --- |
| 偏好 | 你主动告诉它 | 称呼、目标、希望被怎样鼓励 |
| 会话摘要 | 每次确认结算后自动生成 | "11月16日 完成 20 词，错在拼写，用时 25 分钟" |
| 角色摘要 | 由会话摘要提炼 | "这位学习者习惯晚上学，拼写需要更多遍" |

### 它不记什么

- **页面上的点击、翻面、AI 的回复、学习页上报的"完成"事件**——这些都不产生记忆。
- 只有**已经确认结算**的事实才会进入记忆。
- 你在 AI 对话里临时说的话，除非你显式设为偏好，否则不会被记住。

### 隐私：默认不外发

**记忆出站默认是关闭的。** 在你到设置里打开"允许记忆进入 AI 请求"之前，
记忆只在本地保存与展示，不会出现在任何发给模型的内容里。

打开之后，也只有一段**有上限**的背景（最多 5 条、1200 字符）会附在 AI 请求的
系统提示里。你输入的每一条消息都不会被改写。

### 删除

- 删除单条：立即生效，后续提示里不再出现。
- 清空某个角色的记忆：只影响这个角色，其他角色不受影响。
- 清空整个账号的记忆：会要求二次确认（`confirm: true`），删除后不可撤销。

> 说明：删除是"软删除"——行还在库里但被过滤掉。这样误删在未来版本里还有恢复余地，
> 但对你来说效果就是"立即不再出现"。

### 保留期

默认 90 天。过期的**会话**条目会被清理，但**角色摘要**会保留——否则角色会忘记
和你相处很久这件事。

## 二、多角色批量安装

### 怎么用

1. 桌面端：设置 → 角色 → "导入角色包"，原生文件选择器可**多选** ZIP。
   浏览器端：把 ZIP 放进导入目录后由接口检查（浏览器上传在本版本未开放）。
2. 系统先做**检查**：告诉你这个包里有哪些角色、哪些是新的、哪些是升级、
   哪些缺资源（缺资源的会装成"草稿角色"）、需要多少磁盘。
   **这一步不写入任何文件**，可以放心先看。
3. 你确认后开始安装。每个角色独立提交。

### 一个包可以装多个角色

一个 ZIP 里放多个子目录、每个子目录一个角色即可。也支持单角色平铺布局。

### 单角色失败不影响其他角色

`完成 3 个、失败 1 个` 是正常结果，不是整体失败。失败的那个会显示具体原因，
其余角色照常可用。

### 升级保留记忆

如果包里的角色 `role_id` 已经装过，会走**升级**而不是新建。因为沿用同一个
`role_id`，**这个角色的长期记忆与结算历史都会保留**。

升级时**不会覆盖你手改过的人设**，除非包里的清单显式声明
`"replace_persona": true`。

### 检查与确认之间会重新核对

确认安装时系统会重新算一遍 ZIP 的 sha256。如果两次点击之间文件被换掉了，
会拒绝安装——避免"看着 A 装成 B"。

### 安全边界

- 拒绝 `../` 越界路径、绝对路径、盘符路径。
- 拒绝任意下载 URL，只接受本机受控导入目录内的来源。
- 每个角色提交前重新校验清单里的文件名必须是规范名（`gpt.ckpt`、`sovits.pth`、
  `ref.index`、`reference.wav`），不跟随清单里的任意文件名。

### 样本包

生成一个可直接用的双角色包：

```powershell
cd D:\MeMo1
python tests\fixtures\make_role_package.py --out _verification\demo --mode full --count 2
```

会打印路径与 sha256。`--mode draft` 生成缺资源草稿包，`--mode traversal` 生成
用于验证安全拒绝的恶意包。

> 注意：样本包里的 `live2d_model_id` 是占位值。真实使用时请填你已经安装的模型 ID，
> 否则角色会指向不存在的模型。

## 三、进度的含义

界面会显示两个不同的数字，**它们不能互相替代**：

```
本轮  8 / 20 词  ·  25 分钟
今日  目标待确认
```

- **本轮**：你这次打开陪伴模式之后、真正学完的词。这是结算用的数字。
- **今日**：墨墨当天的完整计划进度。只有同步到**完整**今日计划时才会显示真实数字；
  否则显示"目标待确认"。

> 为什么这样设计：如果今日目标没同步完整，界面上的"完成 3 / 10"会骗人。
> 宁可显示"待确认"，也不给一个编造的分母。

### 什么算"真正学完"

同时满足三条：

1. 今日计划**完整**（不是被截断、不缺字段、不是达到 1000 条上限）；
2. 账号身份**已核验**；
3. 这个词在**进入本轮之后**发生了 `false → true` 的转变，并且有本轮参与证据。

第 3 条的具体含义：进入本轮前就已经完成的词，**不算**本轮新增（它会算进"今日"，
但不算"本轮"）。

### 有效时间怎么算

按多个窗口的**区间并集**统计，不累加客户端上报的秒数。

- 两个窗口同时开着，只记一次时间（否则会翻倍）。
- 暂停、心跳中断（超过 45 秒无心跳）、长闲置都不计时。

## 四、结算与奖励

### 什么时候结算

- **本轮目标模式**：本轮确认完成数达到目标。
- **今日计划模式**：今日计划全部完成，且本轮确有新增参与。

满足条件后结算一次，产生：

- 一份结算记录（完成数、新增/复习、有效时间、待巩固的词）；
- 一张**纪念卡**（当天、角色、完成数、薄弱词）；
- 一枚**首次完成**徽章（整个账号只发一次）；
- 一条进入记忆队列的会话事件。

### 为什么重复点击不会重复领奖

结算、纪念卡、徽章、记忆入队各有唯一约束，且在同一事务里提交。
刷新页面、重复提交、两个窗口同时完成，都会返回**同一份**结算。

### 结算演出

- **本地文字立即出现**，不等网络。没有 AI、没有语音、没有动作时，这段文字就是完整体验。
- AI 对同一个结算**最多请求一次**。AI 挂了就静默降级为本地文字，不会刷屏重试。
- **重看历史结算不会重放**语音和动作。
- 如果结算对象已经变了（换了会话或角色），会提示"这一轮记录已更新"并停掉对应语音。

## 五、常见问题

**问：我学了一整天，为什么没有结算？**

按可能性排序：

1. **今天的目标不是完整同步的**。界面显示"今日目标待确认"就是这个意思。
2. **网页身份尚未核验**。本版本没有把网页 iframe 的登录状态与开放 API 账号
   对应起来的证据，因此真实网页学习不会产生结算。这是刻意的安全默认。
3. 你完成的是进入本轮**之前**就已经完成的词，不计本轮新增。

**问：记忆里出现了我不想要的内容？**

设置里可以直接删单条或清空某个角色。删除立即生效。

**问：换角色会丢记忆吗？**

不会。记忆按角色分开存。同一次学习里换角色会切分片段（旧的封存、新的开始），
但两个角色的记忆都各自保留。

**问：升级角色会丢记忆吗？**

不会，只要包里的 `role_id` 与已安装的一致（走升级而非新建）。

**问：数据删了还能找回吗？**

删除是软删除，行还在库里，但当前界面不会显示。真正的"清空"需要显式确认，
且未来版本才可能提供恢复入口——**不要依赖这一点**，重要数据请先备份
（见 `docs/companion-upgrade-migration.md`）。

**问：这些记忆会发给模型吗？**

默认不会。需要你显式打开"允许记忆进入 AI 请求"。

## 六、备份

升级前建议备份：

```powershell
cd D:\MeMo1
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
Copy-Item data\memo-superform.db "data\memo-superform.db.bak-$stamp"
```

应用运行时 SQLite 处于 WAL 模式，直接复制 `.db` 可能拿到不完整状态。
稳妥做法是先停应用再复制，或用 `sqlite3 ... ".backup '...'"`。

完整迁移与回滚步骤见 `docs/companion-upgrade-migration.md`。
